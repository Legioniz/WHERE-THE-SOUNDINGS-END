## Repository root

- Assets/: Unity-owned game assets and C# assemblies.
- Packages/manifest.json: pinned Unity package dependencies; Unity generates packages-lock.json.
- ProjectSettings/ProjectVersion.txt: pinned Unity Editor version.
- docs/: authoritative game design, world, narrative, technical, production, and research documents.
- tools/: offline validation and simulation utilities.
- .github/workflows/: repository integrity automation.

## Greyhaven environment generation

Run Tools > WHERE THE SOUNDINGS END > Initialize Project Foundation on first setup. It creates the initial URP assets and generates Assets/_Project/Scenes/Greyhaven_Blockout.unity.

Use Tools > WHERE THE SOUNDINGS END > Rebuild Greyhaven Environment after changing the environment generator. The command warns before replacing the generated scene. Generated Unity assets and their corresponding .meta files should be committed after successful Editor initialization.

Greyhaven is a working technical greybox. Its coordinates and dimensions are prototype scale values; final terrain, water, architecture, collision, camera framing, UI layout and interaction feel require in-Editor testing. The first cargo-hold interface and Harbourmaster dialogue loop are generated with the scene.

## Rules

1. Keep runtime code independent of Editor APIs.
2. Keep domain algorithms testable without scene objects where practical.
3. Store authored, mostly immutable definitions in ScriptableObjects.
4. Keep mutable world state in runtime models with clear ownership.
5. Isolate third-party assets and maintain their license records.
6. Do not commit Library, Temp, Obj, generated IDE projects, or build output.
7. Save files belong in Application.persistentDataPath and must never be committed to the repository.
8. Do not label a feature implemented until it exists in runtime code and has passed its relevant tests.


## Deep-ocean survey integration

The generated Greyhaven scene attaches DeepOceanSurveyRegion to Sheltered_Bay_Surface and configures it as shallow coastal water. The starter boat receives SoundingRigController, which consumes the existing SoundingPulse Input Action. Greyhaven's profile deliberately reports no deep scattering layer.

The region component contains baseline profiles for all six named regions. Future region scene builders must attach one profile to the correct world / water root and place authored DeepOceanPhenomenonSite markers. Merely having a profile in code does not mean a region scene or site is playable.

The survey subsystem uses AcousticEventBus as the gameplay signal source. Future creature perception should subscribe to this event contract rather than scanning scene AudioSources. Current implementation publishes Sounding Rig pulses only; creature listeners are not yet connected.

Save schema v4 adds survey pulse count, discovered site IDs and evaluated opportunity IDs. See [Deep-Ocean Survey Implementation](DEEP-OCEAN-SURVEY-IMPLEMENTATION.md) for the file-by-file dependency map, runtime flow, tuning assumptions and remaining integration work.

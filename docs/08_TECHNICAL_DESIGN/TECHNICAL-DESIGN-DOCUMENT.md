## Stack

- Unity Editor 6000.3.28f1 (Unity 6.3 LTS).
- C# gameplay code.
- Universal Render Pipeline 17.3.0.
- Unity Input System 1.20.1.
- Unity Test Framework 1.4.6.
- Windows 64-bit first target.

The Editor version is pinned in ProjectSettings/ProjectVersion.txt and packages are declared in Packages/manifest.json. Unity should generate Packages/packages-lock.json on first import.

## Architecture

Separate presentation, gameplay rules, world simulation, authored data, and persistence. Each mutable state has one owner. Prefer small components and explicit interfaces/events. Keep domain calculations testable outside scenes where practical. Use Jobs/Burst only for proven batch workloads; ECS/DOTS and native plugins are optional.

Boundaries: world/time; vessel; fishing/stock; navigation/acoustics; creature AI/director; inventory/economy; quest/narrative; save/load; UI/audio.

## Current project state

The repository now includes:
- Runtime, Editor, and Edit Mode test assemblies.
- Input Action map for keyboard and gamepad.
- Engine-independent WorldClock and PCG32 random stream.
- First-pass Rigidbody boat handling and fixed-angle orthographic camera.
- An Editor setup command that generates URP assets and a Greyhaven blockout scene.
- Static repository validation through tools/validate_project.py and GitHub Actions.

The generated Greyhaven scene is a primitive technical blockout. Boat handling is prototype tuning, not a final physical model. Unity Editor import, C# compilation, Edit Mode tests, and Windows build have not yet been verified in this environment.

## Scenes

The initial scene is Greyhaven_Blockout, generated by Tools > WHERE THE SOUNDINGS END > Initialize Project Foundation. The longer-term target is bootstrap, menu, persistent world shell, harbour content, and region scenes. Choose additive loading only after memory, lighting, and transition tests. Reusable prefabs must not assume fixed scene paths.

## Performance

Preserve docs/technical/PERFORMANCE_AND_LANGUAGE_GUIDANCE.md. 60 FPS is 16.67 ms/frame; 30 FPS is 33.33 ms/frame. These are calculations, not measured project performance. Choose target hardware and budgets before production scales.

## Scope boundary

The scaffold is not a completed vertical slice. Persistence has a versioned JSON foundation and autosave; the starter boat, spatial cargo grid and Yarn variable state have runtime adapters. Dialogue still needs its Yarn Project/Runner and interaction wiring; cargo still needs its player UI, fishing integration, freshness tick and selling/equipment systems. World simulation, creature AI, threat director, full quest runtime, full navigation/acoustics, production audio/UI/art, and release packaging remain to be implemented and validated.

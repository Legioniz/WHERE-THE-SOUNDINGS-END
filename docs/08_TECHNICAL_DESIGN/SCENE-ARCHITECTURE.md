# Scene Architecture

> Project: WHERE THE SOUNDINGS END  
> Status: Greyhaven persistent-scene and six-area additive-scene architecture implemented in source; Unity verification pending  
> Owner: Project lead  
> Version: 0.2  
> Last reviewed: 2026-11-13

## 1. Scene model

Greyhaven is generated by the Editor tooling. The persistent scene is the runtime authority for the vessel, water, simulation, NPCs, dialogue, UI, saves and interaction ownership. Static island scenery is split into additive scenes and loaded around the vessel.

The scene generator and runtime streaming code are the source of truth. Generated scene assets are not currently committed as ready-to-play outputs; a clean Unity setup must run the project bootstrap and Greyhaven rebuild commands.

## 2. Persistent gameplay scene

Greyhaven_Blockout owns:
- Player vessel Rigidbody, boat controller, hydrodynamics, camera and shared Input System action map.
- Water surface mesh and analytic surface sampler.
- Fishing, dredging, sounding and dynamic site interactions.
- RegionalChartController on the persistent vessel, owning physical region-visit detection, chart unlock records and discovered-site filtering.
- SeaStateDirector, atmosphere/horror systems and acoustic event listeners.
- Four NpcAgent residents, schedules, waypoint anchors and Yarn dialogue.
- GreyhavenRuntimeUI, GreyhavenFrontEndUI and the persistent DocksideHubController.
- SaveGameCoordinator, AutosaveController and save participants.
- AreaStreamingDirector and all StreamedAreaDefinition records.

The dockside hub is persistent. It is not a streamed interior scene and does not place scripts or rigidbodies on static area roots. It presents menu-based room descriptions and furniture actions from shore-approach coordinates while the player remains aboard the vessel.

## 3. Additive static area scenes

The Editor builder extracts six static hierarchies:

| Scene | Stable ID | Responsibility |
|---|---|---|
| Greyhaven_Terrain | greyhaven.terrain | Terrain mesh and static basalt outcrops |
| Greyhaven_Harbour | greyhaven.harbour | Piers, breakwaters, racks, crates and static harbour structures |
| Greyhaven_Village | greyhaven.village | Service/residential building shells, roads and static props |
| Greyhaven_Estuary_West | greyhaven.estuary.west | West mudflat and mangrove visuals |
| Greyhaven_Estuary_East | greyhaven.estuary.east | East estuary sediment and mangrove visuals |
| Greyhaven_Lighthouse | greyhaven.lighthouse | Lighthouse tower, lantern room and static bearing light |

Each area contains one inactive StreamedAreaSceneRoot. It must have a stable area ID/revision and static-only contents. Runtime gameplay MonoBehaviours and Rigidbody objects remain in the persistent scene.

## 4. Streaming lifecycle

AreaStreamingDirector uses horizontal vessel distance, preload/unload hysteresis, unload grace, a one-load-at-a-time queue, scene-root validation and asynchronous additive scene operations. Terrain, harbour and village load at startup; estuary halves and lighthouse load on approach.

The queue rechecks distance before a queued load starts. Re-entry during an unload is queued for reload, and the unload coroutine performs a final distance check before deactivating the area root. Invalid areas are rejected rather than partially activated.

Editor/Development Build telemetry reports load duration, referenced mesh/material/texture counts, estimated area asset bytes and global/managed memory counters. Per-area references are not exclusive residency measurements or GPU VRAM measurements.

## 5. Other scenes

OuterShoals_SurveySandbox and HollowTrench_SurveySandbox are generated standalone survey test ranges. They have regional profiles and authored site markers but are not connected by an in-game regional travel system.

## 6. Generated-scene workflow

1. Open the project in Unity 6000.3.28f1.
2. Run Tools > WHERE THE SOUNDINGS END > Initialize Project Foundation on a clean setup.
3. Run Tools > WHERE THE SOUNDINGS END > Rebuild Greyhaven Environment after changing the builder.
4. Confirm the destructive rebuild prompt before replacing generated content.
5. Verify generated static area scenes are included in the active build scene list.
6. Run Edit Mode and Play Mode tests after generation.

Do not edit generated static area roots by attaching runtime scripts or rigidbodies. Update the builder or create a persistent gameplay owner instead.

## 7. Regional chart ownership

The Greyhaven persistent vessel owns RegionalChartController. The controller reads active DeepOceanSurveyRegion bounds and SoundingRigController discoveries, and writes visit/unlock state through the existing save coordinator. It is not attached to streamed static area roots. The GreyhavenRuntimeUI presents the local chart; unknown regions and undiscovered sites are intentionally omitted.

## 8. Verification boundary

GitHub CI validates repository contracts and C# syntax. It does not import Unity assemblies, compile Yarn, regenerate scenes, run Edit Mode/Play Mode tests, measure transition hitches or build Windows.

The six-area transition Play Mode test is authored but has not been executed in Unity. The dockside menu, UI sorting, modal transitions, input focus and checkpoint path also require target-editor verification. See AREA-STREAMING-AND-ASSET-RESIDENCY.md and GREYHAVEN-DOCKSIDE-INTERACTION-HUB.md.
